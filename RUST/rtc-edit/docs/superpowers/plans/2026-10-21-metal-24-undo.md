# Milestone 24: undo and redo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cmd-Z undoes the last change to the scene and Cmd-Shift-Z redoes it, one step per box visit, click, item or follow run.

**Architecture:** A pure `History` in `src/history.rs` keeps copies of the whole scene with a label, merging changes of one open group; `main.rs` records before each change, closes the group when the edited box changes, and swaps scenes on Cmd-Z / Cmd-Shift-Z.

**Tech Stack:** Rust 2024, iced 0.14, rtc-rust's `SceneDescription` (`Clone + PartialEq`).

**Spec:** `RUST/rtc-edit/docs/superpowers/specs/2026-10-21-metal-24-undo-design.md`

## Global Constraints

- Branch `metal/24-undo`; commits end ` (milestone 24)`, prefixes `ENHANCEMENT:` / `TEST:` / `DOCS:` / `FIX:`; never push.
- Depth: 100 steps (`const DEPTH: usize = 100`).
- Status texts: `undid: <label>`, `redid: <label>`, `nothing to undo`, `nothing to redo`.
- Labels: `typing in <row label>`, `closed`, `add <item>`, `delete <item>`, `follow the viewer`, `untick follow`, `empty <row label>`, `change <row label>` (`<row label>` is `describe`'s label, e.g. `position`; `<item>` the tree's lower-case type, e.g. `sphere`, `light`).
- Tests: `cargo test --lib` in `RUST/rtc-edit`; `cargo clippy --all-targets` clean; `cargo fmt`. The "future-incompat … block v0.1.6" warning is pre-existing.
- Test names: descriptive snake_case.

## Review Focus

1. **A typed value that doesn't parse** (red box): the scene doesn't change. Expected: no empty undo step. Task 2: `edit` records only when the scene changed (`before != desc`).
2. **`c` then typing in the same box.** Expected: one step. Task 2: `c` records `Box(node, field)` labelled `change <row label>`, so the typing merges.
3. **Cmd-Z while a box is being edited.** Expected: the box shows the restored value, not the typed text. Task 2: undo clears `editing`/`left` and refills `texts` via `select`.
4. **Undo of a delete restores an item whose node another item now has.** Expected: the restored scene's rows are consistent and the selection stays only if it is still a row. Task 2 by eye.
5. **Undo back to the saved scene, then redo.** Expected: ` •` off, then on. Task 1: `undo_back_to_the_saved_scene_is_not_unsaved`.

### Task 1: `History`

**Files:**
- Create: `RUST/rtc-edit/src/history.rs` (`pub mod history;` in `lib.rs`).

**Interfaces:**
- Produces:
  - `#[derive(Clone, PartialEq, Debug)] pub enum Group { Box(Node, Field), Follow, Once }`.
  - `pub struct History` with `pub fn new(scene: &SceneDescription) -> History` (empty, `scene` saved).
  - `record(&mut self, before: &SceneDescription, group: Group, label: &str)`: `before` is the scene before the change. Same open group (not `Once`) → nothing; else push `(before.clone(), label)`, drop the oldest beyond `DEPTH`, clear redo, open `group` (`Once` opens nothing).
  - `close(&mut self)`.
  - `undo(&mut self, scene: &mut SceneDescription) -> Option<String>` / `redo(...)`: close; pop, push the current scene with that label onto the other list, replace `scene`, return the label.
  - `saved(&mut self, scene: &SceneDescription)`; `differs(&self, scene: &SceneDescription) -> bool`; `clear(&mut self, scene: &SceneDescription)` (empty both lists, close, `scene` saved).

- [ ] **Step 1: Write the failing tests** (a scene from `edit::new_scene()`, changed by setting `camera.field_of_view`):
  - `undo_restores_and_redo_reapplies`: record before fov 1→2, undo → fov 1 and `Some("a")`, redo → fov 2 and `Some("a")`.
  - `one_box_group_is_one_step`: two records with `Box(Node::Camera, Field::FieldOfView)` (1→2, 2→3), one undo → 1.
  - `another_group_or_close_splits`: `Box(Camera, FieldOfView)` then `Box(Camera, Width)` → two undos; same group with `close()` between → two undos; two `Once` → two undos.
  - `a_new_record_clears_redo`: record, undo, record → `redo` is `None`.
  - `the_oldest_step_goes_after_100`: 101 records (fov 0..=101) → 100 undos succeed, the 101st returns `None`, fov is 1.

  - `clear_forgets_everything`: record, `clear(&s2)` → undo `None`, `differs(&s2)` false.
  - `nothing_to_undo_or_redo_leaves_the_scene`: fresh history → `undo`, `redo` `None`, scene unchanged.
